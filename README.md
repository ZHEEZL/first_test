## Содержание работы

Проект реализует требования лабораторного практикума по алгоритмам и структурам данных:

1. **Часть I. Функции и алгоритмы обработки вектора**:
   - Постоянная функция $f(v) = 1$ — $O(1)$
   - Сумма элементов вектора — $O(n)$
   - Произведение элементов вектора — $O(n)$
   - Наивное вычисление значения полинома степени $n-1$ в точке $x = 1.5$ — $O(n^2)$
   - Вычисление полинома по схеме Горнера — $O(n)$
   - Сортировка пузырьком (Bubble sort) — $O(n^2)$
   - Быстрая сортировка (Quick sort) — $O(n \log n)$
   - Гибридная сортировка Timsort (естественные прогоны + бинарная вставка + стек слияний) — $O(n \log n)$

2. **Часть II. Матричные вычисления**:
   - Классическое матричное произведение случайных матриц $A \times B$ размера $n \times n$ — $O(n^3)$
   - **Прямоугольное умножение $A(M \times N) \times B(N \times M) \rightarrow C(M \times M)$** с построением **3D графика сложности в координатах $T \times M \times N$** (оси $T, M, N$, числовые засечки, координатная сетка пола $T=0$, каркас и проекция) и **двумерной тепловой карты (Heatmap)**.

3. **Часть III. Индивидуальные нетривиальные алгоритмы**:
   - **Древовидная сортировка (Tree sort через BST)**:
     - **В среднем (на случайных данных)**: теоретическая сложность **$O(n \log n)$**. Построение несбалансированного бинарного дерева поиска (BST) с пулом узлов без аллокаций памяти в куче и последующим итеративным симметричным обходом (In-order traversal: Left $\rightarrow$ Node $\rightarrow$ Right).
     - **В худшем случае (на отсортированных данных)**: деградация до **$O(n^2)$**. На предварительно отсортированном входе каждый новый элемент строго больше предыдущего, поэтому дерево поиска вырождается в односвязный список («бамбук») глубины $n$, что требует $\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2} \sim \frac{1}{2} n^2$ сравнений. В программе реализован отдельный замер худшего случая, наглядно демонстрирующий параболическую деградацию (замедление более чем в 54 раза: 56 мкс $\rightarrow$ 3.04 мс).
   - **Поразрядная сортировка (Radix sort, LSD)** — теоретическая сложность **$O(n)$**. Реализован LSD (Least Significant Digit) Radix Sort по 8-битным разрядам (8 проходов × 256 корзин) над 64-битным IEEE-754 представлением вещественных чисел `double`. Для корректной сортировки знаковых вещественных чисел используется монотонное отображение `FloatFlip` (XOR-инверсия, сохраняющая порядок `double` при побитовом сравнении). Работает за **линейное время** $O(n)$, что наглядно демонстрирует отличие от квадратичных и квазилинейных сортировок.

4. **Часть IV. Алгоритмы возведения в степень (подсчёт элементарных операций)**:
   - **Простой итеративный** (Рис. 1 методички: последовательное умножение) — $O(n)$ шагов.
   - **Рекурсивный по определению** ($x^n = x \cdot x^{n-1}$, п. 11 программы) — $O(n)$ шагов (линейная глубина стека $n$, ровно $n$ умножений).
   - **Рекурсивный бинарный RecPow** (Рис. 2 методички: деление степени пополам $n / 2$) — $O(\log n)$ шагов.
   - **Быстрый алгоритм QuickPow** (Рис. 3 методички: старшие биты вперёд) — $O(\log n)$ шагов.
   - **Классический быстрый алгоритм QuickPow1** (Рис. 4 методички: младшие биты вперёд) — $O(\log n)$ шагов.
   - *Примечание о совпадении шагов у RecPow и QuickPow*: на $n=2000$ оба алгоритма дают ровно **17 операций умножения**. Это не дубликат кода, а прямое следствие двоичного разложения: $2000_{10} = 11111010000_2$ (длина 11 бит, 7 единиц). И рекурсивный `RecPow` (деление пополам), и итеративный `QuickPow` выполняют ровно 10 возведений в квадрат и 7 домножений на $x$ ($10 + 7 = 17$).

## Архитектура и инженерные решения

### 1. Измерительный контур и префиксы данных
- **Базовый вектор $V$**: генерируется один раз в классе `ExperimentContext` с фиксированным seed и **никогда не модифицируется**.
- **Префиксы**: для каждого значения $n$ берется неизменный срез первых $n$ элементов ($n = Step, 2 \cdot Step, \dots, MaxN$). Сортировки клонируют префикс в буфер `Work` вне тайминга замера.
- **Стабилизация CPU, JIT и GC**:
  - **Отключение Tiered Compilation**: в `.csproj` задан параметр `<TieredCompilation>false</TieredCompilation>`. Это отключает двухъярусный JIT .NET 8 (Tier 0 QuickJIT), заставляя компилятор сразу создавать максимально оптимизированный машинный код (Tier 1) без скачков посреди серии измерений.
  - **Сборщик мусора (GC)**: отключены серверный и конкурентный режимы (`<ServerGarbageCollection>false</ServerGarbageCollection>`, `<ConcurrentGarbageCollection>false</ConcurrentGarbageCollection>`). Перед замерами вызывается `CleanHeap()` с двукратным `GC.Collect()` и ожиданием финализаторов, исключая срабатывание фонового сборщика посреди цикла тайминга.
  - **Привязка к ядру (Processor Affinity)**: процесс фиксируется на логическом ядре 0 (`Process.GetCurrentProcess().ProcessorAffinity = (IntPtr)1;`), что устраняет миграцию потока между ядрами операционной системы и исключает скачки между ядрами. *(Примечание: на гибридных CPU с P- и E-ядрами физическое назначение ядра 0 зависит от топологии BIOS/ОС, однако фиксация маски на одном ядре в любом случае гарантирует стабильность и отсутствие миграции потока)*.
  - **Приоритет потока**: процесс переводится в `ProcessPriorityClass.High`, а измерительный поток — в `ThreadPriority.Highest`, что сводит к минимуму вытеснение планировщиком Windows сторонними процессами.
  - **Двухуровневый прогрев (Warmup)**:
    - *Глобальный (`GlobalWarmup`)*: разогревает структуры данных, кэширует вспомогательные методы и выполняет 100 мс спиннинга CPU (`Math.Sin`) для вывода ядра из глубоких энергосберегающих состояний сна (C-states: C1/C2/C3...) в активное состояние C0/P-state до старта серии.
    - *Локальный (на каждом шаге $n$)*: перед 5 «боевыми» прогонами выполняется один холостой проход алгоритма на текущем срезе $n$, разогревающий L1/L2 кэш и таблицы предсказания ветвлений (Branch Target Buffer) под конкретный объем данных.
- **Фильтрация выбросов**: метод `RobustMean` использует модифицированную $z$-оценку на базе медианного абсолютного отклонения (MAD) с порогом $3.5 \cdot \text{MAD} / 0.6745$.
- **Пользовательский формат времени**: исключено представление в научной нотации вида `e^-6`. Везде в интерфейсе, логах, таблицах и на осях графиков используется динамический перевод в понятные единицы (`нс`, `мкс`, `мс`, `с`).

### 2. База данных SQLite и умное кэширование
- Модуль `BenchmarkDb.cs` (`benchmark.db`) сохраняет результаты всех индивидуальных повторов с транзакционной группировкой.
- **Кэширование**: если для алгоритма при данном $n$ и количестве повторов данные уже есть в БД, точка подтягивается моментально (повторный прогон 17 алгоритмов занимает **0.2 секунды** вместо 48 с).
- В интерфейсе и консоли предусмотрена опция принудительного перерасчета в обход кэша (`--force`).

### 3. Оценка точности (MSE)
Для каждого алгоритма вычисляется среднеквадратичная ошибка аппроксимации:
$$MSE = \frac{1}{k} \sum_{i=1}^{k} \left( y_{\text{эмпирическое}}(n_i) - C \cdot f(n_i) \right)^2$$
где коэффициент $C$ находится методом наименьших квадратов (МНК). Ошибка выводится в сводной таблице, заголовках графиков и экспортируемом CSV.

### 4. Вкладка «3D График (T × M × N)»
- Позволяет исследовать время умножения прямоугольных матриц $A(M \times N) \times B(N \times M)$ в зависимости от двух параметров: строк $M$ и столбцов $N$ со сложностью $O(M^2 \cdot N)$.
- Строит полноценный трехмерный график в координатах $T \times M \times N$ с осями $T, M, N$, числовыми засечками, сеткой пола $(M, N)$ при $T=0$, 3D каркасом параллелепипеда и возможностью интерактивного вращения в реальном времени (ползунки Yaw и Pitch).
- Поддерживает переключение на двумерную цветовую карту (Heatmap) с цветовой шкалой `Turbo`.

### 5. Вкладка «Сравнение из истории»
- Позволяет выбрать сохранённые сессии экспериментов из базы SQLite.
- Выбрать интересующий алгоритм и построить сравнительный график с наложением кривых разных запусков на одной координатной плоскости.

## Сборка и запуск

### Требования
- [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- Кроссплатформенная поддержка (Windows 10/11, macOS, Linux) благодаря стеку Avalonia UI 11.

### 1. Оконный интерфейс (GUI)
```powershell
dotnet run --project first
```
В интерфейсе доступны:
- Выбор алгоритмов галочками.
- Редактирование $Max N$, шага сетки ($Step$) и количества повторов ($Runs$) прямо в таблице.
- Кнопка сброса параметров к дефолтным значениям.
- Чекбоксы включения/отключения кэша SQLite и глобального прогрева.
- Вкладки в стиле браузера с интерактивными графиками ScottPlot (панорамирование, инспекция координат точек курсором, экспорт).
- Кликабельная сводная таблица: клик или Enter по строке алгоритма мгновенно переходит на вкладку соответствующего графика (или восстанавливает её при закрытии).
- Полнофункциональный интерактивный 3D-график $T \times M \times N$ и Heatmap на движке SkiaSharp.
- Вкладка «Сравнение из истории» с наложением кривых разных сессий.
- Экспорт таблицы в CSV и графиков в PNG.

### 2. Консольный режим (без открытия окна)
```powershell
dotnet run --project first -- --no-window
```
С принудительным пересчётом в обход кэша SQLite:
```powershell
dotnet run --project first -- --no-window --force
```
Автоматически проводит прогрев JIT/памяти/CPU, запускает замеры всех 17 алгоритмов, выводит сводную таблицу в консоль, сохраняет результаты в `results.csv`, графики в папку `charts/` и обновляет `benchmark.db`.

### 3. Диагностика влияния холодного старта JIT и CPU
```powershell
dotnet run --project first -- --check-init
```
Демонстрирует разницу между первым «холодным» вызовом метода и прогретым (ускорение до $\times 600..900$ раз).
